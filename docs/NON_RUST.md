# Non-Rust Components

The Sheffield Family Calendar & Routine Hub stack is **Rust whole-stack**, with the following declared exceptions:

| Component | Purpose | Justification | Notes |
| --- | --- | --- | --- |
| `sw.js` | Service Worker (~105 lines, 3.3 KB; ≤ 6 KB budget asserted by `tests/pwa_tests.rs`) | Served from Rust at `/sw.js`; app-shell precache, network-first server fns, cache-first `/uploads` + screensaver. No Background Sync (`docs/PWA.md`) | `include_str!`'d from `src/client/components/mobile/sw.js` (T2.2) |
| `tailwindcss-windows-x64` v3.4.17 | CSS build-time compiler (binary) | Standalone Tailwind CLI for Windows; v4 is incompatible with our config model and has no Rust equivalent | Downloaded as a binary; runs at build time only |
| Fully Kiosk Browser ≥ 1.61.2 | Kiosk shell on Fire TV (Branch A) | Proprietary launcher; PLUS licence ~€8.90/$10.99 one-off | Fire OS only; one of three runbook branches (A/B/B′); sideloaded via adb |
| `adb` (Android Debug Bridge) | Fire TV configuration tool | Granting SYSTEM_ALERT_WINDOW and GET_USAGE_STATS permissions; setting sleep timeout; toggling HDMI-CEC | One-time device setup by the owner; also shelled out to at runtime by `family-hub.exe tv-probe` (T3.1, via `server::service::CommandRunner`, best-effort, never in the service path itself) |
| GitHub Actions YAML (`.github/workflows/`) | CI/CD pipeline definition | Declarative workflow for build, test, lint, release automation | Not code executed by the app; configuration only |
| `wasm-bindgen` glue | WebAssembly FFI bindings | Browser APIs (canvas, events, storage); generated from `web-sys` types at compile time | Included in the Dioxus build process; transparent to Rust code |
| Browser / WebView | Runtime execution | Fire TV: Amazon Silk (Vega OS) or Fully Kiosk; phones: Chrome (Android) or Safari (iOS) | Third-party; outside our control; tested against via the app's HTTP interface |
| Amazon Silk (Vega OS Branch B) | Kiosk shell on Fire TV (alternative) | Native browser on newer Fire TV models (Vega OS 2024+); no sideload required | Optional branch; fallback if Fully Kiosk unavailable |
| Android SDK (Phase C; **not in this run**) | Native Android app shell (cut) | WebView host for a Rust-native Android wrapper; full D-pad integration | **Deferred indefinitely**; kept in docs for completeness |
| `icacls.exe` (Windows built-in) | Narrow the NTFS ACL on `<data>\pki\*.key` when a key is first written (§P5.5 default 7, T1.3) | OS built-in invoked at runtime; best-effort, failure is logged and never fatal. T3.1 adds `netsh.exe` / `sc.exe` rows on the same basis | No download; present on every Windows 11 install |
| `kernel32.dll::GetDiskFreeSpaceExW` (Windows built-in) | `/health`'s `disk_free_bytes` on the data volume (T1.7) | OS API reached by a direct `extern "system"` FFI call — no crate, no spawned process; same "OS built-in at runtime" basis as the `icacls.exe` row. Failure yields `null`, never an error | No download; present on every Windows 11 install |
| `wasm_bindgen(inline_js)` snippet in `src/client/components/routine.rs` (~45 lines of JS) | Phone-side photo downscale + multipart upload (T2.5): `createImageBitmap` → `<canvas>` `drawImage` → `toBlob('image/jpeg', 0.85)` → `fetch('/api/upload_photo')` | Reaching that pipeline through `web-sys` needs half a dozen extra feature flags on a Boss-owned `Cargo.toml`; the snippet is a bandwidth optimisation only — the server re-sniffs, re-decodes and re-encodes every upload regardless (`api::photos`) | Compiled into the wasm bundle by the existing `wasm-bindgen` glue row; runs only on `feature = "web"` + `wasm32`; the non-wasm stub returns `false`. Added by Boss at the 2-a rerun close |
| `netsh.exe` (Windows built-in) | `family-hub.exe install` adds three inbound firewall rules (TCP 8080/8443, UDP 5353 — D9, PURPLE §P3 T3.1(d)) | OS built-in invoked at runtime, on the same "no crate, no PowerShell script" basis as the `icacls.exe` row (`docs/HANDOFF.md` H-12, ratified: "T3.1 adds `netsh.exe` ... rows on the same basis"); best-effort, a failure is logged and never blocks the rest of `install` | No download; present on every Windows 11 install. Shelled out to via `std::process::Command` behind `server::service::CommandRunner`, which unit tests replace with an in-process recorder (`docs/reviews/PURPLE_TEAM.md` §P3 T3.1: "unit-tested against a mocked service_manager") |
| `powercfg.exe` (Windows built-in) | `family-hub.exe install` sets the power plan to never sleep/hibernate/turn off the display on AC power (D9) | Same basis as `netsh.exe` above; best-effort, non-fatal | No download; present on every Windows 11 install |
| `advapi32.dll::RegisterEventSourceW`/`ReportEventW`/`DeregisterEventSource` (Windows built-in) | `server::service::ServiceLogger` mirrors service log events to the Windows Event Log (D9: "file + Event Log logging as the first statement") | OS API reached by a direct `extern "system"` FFI call — no crate, no spawned process; same basis as the `kernel32.dll::GetDiskFreeSpaceExW` row. Best-effort: a missing registry-registered event source still accepts the call, and any failure is silently swallowed rather than blocking the file write | No download; present on every Windows 11 install |
