# RED TEAM review of `docs/PLAN.md`

**Reviewer:** Red Team (adversarial)
**Date:** 2026-08-29
**Target:** `docs/PLAN.md` DRAFT v1
**Basis:** full read of `PLAN.md`, `README.md`, `Cargo.toml`, `Cargo.lock`, all 2,029 lines under `src/` and `tests/`; live inspection of the dev box; and external fact-checking of the Dioxus 0.7 migration surface, Fire OS / Fully Kiosk behaviour, and the Rust crates the plan depends on.

**Verdict in one line:** the plan's *diagnosis* of the codebase is largely accurate and unusually honest, but its three load-bearing external bets — the Fire TV runs Fire OS and can be sideloaded, a user CA can be installed on it, and the Dioxus 0.7 migration is a version bump — range from unverified to demonstrably wrong, and its central promise of checkpoint-free autonomy is contradicted by its own acceptance criteria.

**Read R-01 through R-03 before approving anything.** They can invalidate D1, D2, D3, D8, Phase 2 and Phase C outright, and all three are answerable in a day with the hardware already in the house.

## Cross-cutting judgements

### What the plan gets right

G1–G19 are, with the caveats below, accurate — I checked each against the source and found **no fabricated findings**. G3, G5, G8, G13, G14 and G18 are all real and correctly characterised. D1's core insight (the TV is a display), D5's server-authoritative envelope split, and D4's move to SQLite as the source of truth are sound. §7 asks reviewers to hammer exactly the right places. The failure mode is not dishonesty — it is that several §7 risks are flagged and then **scheduled as though already resolved**, and that the plan's confidence is calibrated to a codebase nobody has built.

Two of the plan's own worries can be **downgraded**: R3's concern about "Amazon WebView feature gaps (Pointer Events, canvas)" is largely unfounded — the latest Fire OS 7 and 8 builds ship Chromium ~120–124, which is entirely adequate for canvas, service workers and WebSockets (the horror stories date from Chromium 58-era builds). And R6's Windows/Bonjour concern is a non-issue (R-09).

### Where §1 is wrong or thin

- Line count is 2,029, not 2,041 — trivial in itself, symptomatic of unverified numbers.
- "Solid; tests are real" overstates coverage: all 8 tests are database tests (R-21).
- G3 understates the failure — outbound dies too, and the **server** closes the socket (R-06).
- G5 misses that the whiteboard drops segments while fully connected (R-22).
- G6 misses the manifest-scope blocker, which is the actual reason install is refused (R-16).
- G10 misses that the event cache is in-memory only and that an empty day never propagates (R-28).
- G14 is graded Med but is a hard 2 MB failure, not a rough edge (R-08).
- G15/D7 mis-describe the migration and overstate "end-of-life" (R-07).
- **Missing entirely:** no delete path for custom tasks anywhere in code or plan (R-18); no ownership check on `toggle_custom_task` (R-23); DST bug in `rfc3339_local` (R-28); CWD-relative data paths (R-14); WAL/journal mode never set (R-20); the redundant `native-tls`/OpenSSL dependency (R-26).

### The three things most likely to sink this

1. **The device.** If it is a Vega Fire TV, the kiosk plan is void (R-01). If it is Fire OS 8, the CA may be uninstallable (R-02). Either answer rewrites D2, D3, D8 and Phase 2.
2. **The kiosk layer is unproven and scheduled last** (R-03, R-11), and its own vendor advises against this exact configuration.
3. **The plan promises autonomy it cannot deliver** (R-05), so the failures above will be reported as successes until the owner stands in the living room.

### Recommended re-shaping (minimal)

Insert a **Phase −1 spike before approval** — roughly a day, using hardware already in the house:

1. Read the Fire TV model and Fire OS build off the device (R-01).
2. Install the Rust toolchain; get `cargo test --features server` green on Windows (R-04).
3. Put the current 0.6.3 build on the real Fire TV via Fully Kiosk 1.61.2 over plain HTTP; capture the remote's actual key codes; reboot three times (R-03, R-11).
4. Attempt a user-CA install on the Fire TV and on one phone of each OS (R-02).

Those four answers determine D2, D3, D8 and half of Phase 2. **Everything else in this review is cheaper to fix now than to discover in Phase 3.**
